# Reading first iteration

This iteration follows hands-on feedback: capture worked, but watching the trail competed with reading; the map did not provide a starting point; explanations were brief; source disclosures closed on background updates; and self-assessment was not the preferred review flow.

## What changed

- **Read without sidebar:** the side-panel header has a minimize control. It enables a small rabbit on included pages and closes the global panel on Chrome 141+. Older Chrome versions can close the panel with Chrome’s own close button. Hover or keyboard-focus the rabbit for Pause/Resume and Hide. Click it to reopen RabbitHole. It is static and shows collection state, not AI processing. Hide removes the indicator without changing collection state.
- **Save text selections automatically:** explicit per-session opt-in under Session preferences. A completed pointer or keyboard selection is saved after a 750ms pause. The selected text must remain unchanged. Programmatic page selections do not arm capture. Inputs, textareas, editable content and ranges crossing them are excluded. Worker-side membership, pause, exclusion and opt-in checks still apply. Manual shortcuts/context menu remain available. Duplicate highlights are deduplicated.
- **A navigable map:** radial overview starts with the main idea and major branches. Choosing a branch reveals its details; Overview returns to the starting point; Show all ideas restores the full graph. Only saved relationships are drawn. Parent IDs are an organizing hierarchy, not factual edges. Older maps use graph structure to choose a clearly labelled layout hub. The chronological evidence-depth view and accessible list remain available. The session rail is optional to give the map more room.
- **A useful inspector:** explanation comes before takeaways, an illustrative example and its limits. Short source excerpts replace the initial wall of captured text; the full captured text stays expandable. A stable inspector component preserves disclosures across background changes. Static edges replace animated reveal masks.
- **Objective review first:** Practice defaults to Quiz; map connections open relevant quiz questions when available. Four-choice questions use a 2×2 layout. The chosen answer is recorded immediately, with the saved explanation and per-option reasons when supplied by Go. Matching pairs are generated by Go and checked against their saved key. Quiz/matching ratings cannot contradict their objective answer at the backend. Open-response self-assessment and flashcards remain optional.
- **Richer Go output:** optional overview/root/route, parent hierarchy, concept takeaways/examples/boundaries, exact evidence excerpts, quiz choice explanations and matching pairs. Optional fields keep earlier saved maps readable. The backend rejects invented excerpts and invalid hierarchy references/cycles. It cannot determine whether every generated interpretation or answer is substantively correct; source inspection remains important.
- **Explicit rebuild:** Rebuild with Go copies a prompt and opens the agent. After retrieving the existing evidence, Go may save a rebuilt complete guide with `intent: "rebuild"`, a current expected version and no invented new captures. Ordinary zero-pending runs remain no-ops. Stable unchanged study IDs keep their attempts; materially rewritten questions should receive new IDs. The extension observes saved versions; opening Go does not start processing.

## Verification

`npm run check`: 28 focused tests, TypeScript and production build. The official MCP transport test now also exercises an explicit rebuild with existing evidence and retrieves its saved overview and hierarchy.

The packaged Chromium harness uses a temporary profile, synthetic research pages, synthetic analysis and a synthetic handoff destination. It tests opt-in/off automatic selection, genuine pointer selection, programmatic and editable exclusion, compact indicator pause/resume/hide, changed-storage disclosure retention, radial overview/branch/full-map/trail navigation, static map with motion enabled, keyboard controls, quiz default and immediate result persistence, matching grading/persistence, 320px light/dark, local fonts, reduced motion, offline/paused/handoff states and existing capture/restart/retry/delete regressions. Native side-panel close/reopen gestures and native permission prompts are not established by a headless extension-page test. Native close uses the documented Chrome API with a manual-close fallback; reopening uses a synchronous user-gesture message handler.

Use Rebuild with Go, paste/send the prompt and approve its proposed save. The new wording's usefulness needs a fresh real-source run; passing schema/UI tests does not establish that quality.

## What stays deferred

Scheduled processing, déjà vu reminders, cross-session maps, memory-strength displays, a full activity ladder, daily reviews and additional mini-games. The next decision should follow a real reading/rebuild/quiz session: are the explanations specific to the trail, does each answer have defensible evidence, and is returning to the sources easier than retracing browser history?
